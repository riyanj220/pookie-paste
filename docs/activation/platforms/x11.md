# X11 Activation & Paste

This document details the X11 platform implementation of window focus restoration and synthetic paste injection in Pookie Paste.

For the common activation lifecycle, see [Activation Overview](../overview.md).

---

## Target Identity

On X11, window targets are represented by their X11 window resource identifier:

```rust
FocusTarget::X11(u64)
```

In IPC messages, this corresponds to `IpcFocusTarget::X11(u64)`.

---

## Focus Management ([`crates/daemon/src/x11_focus_backend.rs`](../../../crates/daemon/src/x11_focus_backend.rs))

X11 focus operations interact with the EWMH (Extended Window Manager Hints) specification using the `x11rb` library.

### 1. Active Window Capture
The backend connects to the X server and queries the root window for the `_NET_ACTIVE_WINDOW` property:

1. Resolves the `_NET_ACTIVE_WINDOW` atom via `intern_atom()`.
2. Calls `get_property()` on the root window for `AtomEnum::WINDOW` data.
3. Reads the 32-bit window handle from the property reply.
4. If a non-zero window ID is returned, it is stored as `FocusTarget::X11(id)`.

### 2. Focus Restoration Request
To request that the window manager give focus back to the original application, Pookie sends an EWMH client message rather than directly forcing input focus:

1. Constructs a `ClientMessageEvent` for the target window:
   * **Type**: `_NET_ACTIVE_WINDOW` atom.
   * **Format**: 32.
   * **Data**: `[1, CURRENT_TIME, 0, 0, 0]` (where `1` indicates a normal client application request according to the EWMH specification).
2. Dispatches the event to the root window using `SUBSTRUCTURE_REDIRECT | SUBSTRUCTURE_NOTIFY` masks.
3. Calls `connection.flush()` to ensure the message is immediately delivered to the window manager.

### 3. Confirmation
The daemon polling loop repeatedly invokes `is_active(target)`:
* It reads `_NET_ACTIVE_WINDOW` from the root window.
* Focus is confirmed when the returned window ID matches the target window ID.
* If a non-X11 target variant is supplied, it is immediately rejected with a platform mismatch error.

## Paste Injection ([`crates/daemon/src/x11_paste_backend.rs`](../../../crates/daemon/src/x11_paste_backend.rs))

Synthetic paste injection on X11 uses the standard XTest extension (`xtest_fake_input`).

### 1. Dynamic Keycode Resolution
Keycodes vary across keyboard layouts and hardware. Pookie does not hardcode static key numbers. Instead, it queries the X server keymap dynamically:
1. Calls `get_keyboard_mapping()` from `min_keycode` to `max_keycode`.
2. Resolves keysym `XK_CONTROL_L` (`0xffe3`) to find the current Left Control keycode.
3. Resolves keysym `XK_V` (`0x0076`) to find the current 'V' keycode.

### 2. Keystroke Synthesis
Using `xtest_fake_input`, the backend dispatches a four-step sequence:
1. **Press Left Control** (Event type 2, `control_keycode`).
2. **Press V** (Event type 2, `v_keycode`).
3. **Release V** (Event type 3, `v_keycode`).
4. **Release Left Control** (Event type 3, `control_keycode`).
5. Calls `connection.sync()` to ensure all events are fully processed by the X server before the backend returns.
